# Реальный запуск CatBoost на проверенных данных 2023

Этот комплект позволяет разработчику подключить кнопку фронтенда к реальному выполнению CatBoost. На запросе модель загружается из `model.cbm`, признаки рассчитываются из паспорта и истории, затем вызывается `model.predict`. Готовые прогнозы и фактические толщины runtime не читает.

## Что передать разработчику

Весь архив. Основной вход — `data/request_2023.json`. Это полный JSON-запрос на 147 сегментов девяти объектов с паспортами, очищенной историей до 2023 года и датами прогноза. Его можно отправить в POST /predict. Никаких фактических толщин 2023 в этом запросе нет. В history поле target_mm означает ПРОШЛЫЙ замер 2018/2022, а не ответ 2023.

- `model.cbm`, `metadata.json` — модель и её версия/схема.
- `predictor.py` — построение признаков и вызов CatBoost, перевод результата в мм.
- `run_inference.py` — сервисная функция `PredictionService.predict(payload)` и пакетный запуск.
- `serve.py` — минимальный локальный HTTP-пример, POST /predict и GET /health. В рабочем продукте сервисную функцию нужно встроить в существующий бэкенд с его обработкой ошибок, авторизацией и настройками, а не подменять весь сервер этим примером.
- `requirements.txt` — проверенные зависимости, Python 3.12.
- `data/assets.csv`, `data/history_pre2023.csv`, `data/requested_segments.csv` — тот же вход в табличном виде. История содержит 91 строку релевантных объектов; у остальных объектов история отсутствует. Наличие отсутствующей истории допустимо; сбой загрузки истории нельзя выдавать за её отсутствие.
- `reference/actual_2023.csv` — фактические толщины для сравнения ПОСЛЕ прогноза.
- `reference/expected_predictions_2023.csv`, `reference/expected_features_2023.csv` — эталон для проверки интеграции, не источник ответа API.
- `reference/pot_south.csv`, `reference/vtd_south_train.csv` — исходные паспорта и ВТД для трассировки; содержат данные вне runtime-выборки, включая ответы 2023. Не передавать их напрямую вместо подготовленного запроса.
- `reference/observed_history_all_years.csv` — очищенные минимумы всех лет; не загружать в runtime вместо history_pre2023.
- `training/train_932.csv` — 932 обучающие строки: фактически использованные признаки, номинал и таргет. Переобучать для демонстрации не требуется.
- `FEATURE_CONTRACT_RU.md` — подробные формулы и ограничения исходного адаптера. Упомянутые там старые fixtures заменены в этом комплекте на data/ и reference/; актуальные команды ниже.
- `verify.py`, `verification.json` — воспроизводимая проверка настоящего HTTP-вызова и запуска в изолированной папке без эталонов.

## Запуск из распакованной папки

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python verify.py
python serve.py --port 8000
```

В другом терминале из той же папки:

```bash
curl --fail-with-body http://127.0.0.1:8000/predict \
  -H 'Content-Type: application/json' \
  --data-binary @data/request_2023.json \
  -o predictions_2023.json
```

Без HTTP:

```bash
python run_inference.py --input data/request_2023.json --output predictions_2023.json
```

Для HTTP-проверки среда должна разрешать слушать локальный порт. При проверке сервер запускается на свободном порту и завершается автоматически.

## Как подключить кнопку

В существующем бэкенде создать один `PredictionService()` при старте процесса. Маршрут прогноза должен передавать полученный JSON в `service.predict(payload)` и возвращать результат. Если данные хранятся в базе, бэкенд формирует такой же payload из базы. Фронтенд по нажатию кнопки делает POST и отображает ответ; не читает expected_predictions_2023.csv как результат модели. Для демонстрации можно загружать готовый data/request_2023.json. Передавать исторические измерения через фронтенд в промышленном варианте необязательно — их может получать сам сервер.

Ответ содержит `model_id`, `unit: mm`, `count: 147` и `predictions`: для каждой строки `id`, `segment_id`, `date`, `prediction_mm`. Для показа факт/прогноз сопоставить ответ с actual_2023.csv по тройке (id, segment_id, date), а не по номеру строки. Факт хранить отдельно от входа модели. Успешный результат должен возвращаться только после реального вычисления; не заменять ошибки модели заранее сохранёнными значениями.

Фронтенд должен обращаться через существующий бэкенд/прокси того же происхождения. Пример serve.py не настраивает CORS, авторизацию и промышленный сервер; это задача интеграции с существующим проектом.

## Что уже проверено

Настоящий POST /predict возвращает 147 прогнозов; максимальная разница с эталоном — 0 мм. Дополнительно во временную папку скопированы только модель, metadata, два runtime-модуля и запрос: ни фактических ответов, ни готовых прогнозов там нет. Получен идентичный JSON-результат. Pearson r = 0.7186762831, r² = 0.5164955999. Исходные данные и модель не изменялись.

## Важные границы

Это cb_history_d6_MAE, а НЕ нейросеть и НЕ CatBoost без истории. Модель использует положение/возраст сегмента и прошлую толщину своего/соседних сегментов. Эксплуатационные параметры не используются, поэтому их файлы не нужны для работы этой версии. Изменение давления/температуры в интерфейсе не должно обещать изменение прогноза этой модели.

История строго до даты прогноза и до 2023-01-01. Эта фиксированная политика сохранена для воспроизведения оценки, а не автоматически продлена на будущие годы. Выход нативного CatBoost — доля номинала; адаптер переводит её в мм. Не применять повторное умножение в бэкенде.

147 сегментов — места с зарегистрированными потерями металла, не все сегменты объектов. Сопоставимость истории имеет ограничения; общая корреляция в основном включает различия объектов, внутри объектов она слабая. Оценка ретроспективная. Данные реальные и предназначены для внутренней интеграции; не выкладывать reference/training в публичный фронтенд.
