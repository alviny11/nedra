# Допущения и ограничения

## Что синтетическое
* Объект (топология, рельеф, длины, диаметры, оборудование, датчики) — условный, не воспроизводит реальное месторождение.
* Нефть и эмульсия — синтетические параметры (`provenance: synthetic`), не лабораторный паспорт; модель вязкости эмульсии не откалибрована.
* Вода — табличная вязкость **чистой** воды; солёность не учтена.
* Измерительный шум, флуктуации границ (процесс Орнштейна–Уленбека), расхождение «истина/паспорт» (вязкость ×0.95…1.25, шероховатость ×0.9…1.5, модуль упругости ×0.95…1.03) — синтетические.
* Все метрики испытаний получены на синтетике одного объекта и не являются оценкой промышленной надёжности.

## Что не моделируется (или моделируется упрощённо)
* Газосодержащий участок до сепарации (M1) — только акустический калькулятор Вуда; нет фазового обмена, скольжения, пробок; утечка газа и газожидкостной смеси **не моделируется** (только формулы идеального газа в тестах).
* Консервативный решатель с переменной плотностью/составом (режим 2) не реализован: в M0 опорные ρ и c трубы фиксированы на прогон; изменение состава влияет только на вязкость (и теплоёмкость), но не на гидростатику и скорость волны.
* Сепаратор, УПН, ёмкость, КНС — границы давления; уровень/давление аппаратов, регуляторы, дегазация в ёмкости не моделируются; волна через аппарат не передаётся.
* Нестационарное трение (Zielke/Vardy/Brunone), вязкоупругость стенки, кавитация и разрыв сплошности, неньютоновская реология, теплопроводность грунта (только постоянный U), осевая теплопроводность жидкости.
* Обратный приток через отверстие утечки (`p ≤ p_ext`) — остановка расчёта с сообщением.
* Пласт и скважины, коррозия, противоаварийная автоматика, многопользовательская безопасность.

## Численные
* Интерполяция в основании характеристики при Cr < 1 размазывает фронты (короткая труба e1: Cr = 0.88).
* Коэффициент трения в MOC запаздывает не более чем на 0.1 с.
* Узел утечки привязывается к ближайшему узлу сетки (ошибка ≤ Δx/2 ≈ 12 м, показывается оператору).
* Перенос температуры/состава — второй порядок в пространстве (MUSCL), первый во времени с расщеплением.

## Диагностика
* Наблюдатель использует измеренные граничные условия; ошибки граничных датчиков переходят в прогноз.
* Калибровочное окно (до 180 с) предполагается без событий; событие в нём испортит нормировку.
* Интервал локализации — множество допустимых кандидатов, а не статистически калиброванный доверительный интервал.
* Score и «опора» кандидатов — не вероятности. Вероятности классификатора показываются как откалиброванные только при ECE ≤ 0.05 на валидации; на сдвинутых условиях (OOD) калибровка ухудшается — см. `docs/validation.md`.
* **Слепая зона**: участок e7 после расходомера FT-104 (≈ 50 м до границы давления УПН) не входит ни в одну зону баланса, а давление там задаёт граница — утечка в этом месте практически ненаблюдаема при данной расстановке датчиков (пример — пропуск в ood-v1).
* Утечка, которую видит только один расходомер (баланс + один прибор, без падения давления и фронта), физически не отличима от плавного дрейфа этого расходомера: D1 даёт «неоднозначно», D2 может подтвердить утечку по классификатору с пометкой `SINGLE_METER`. Ложная тревога D2 при отрицательном дрейфе выходного расходомера возможна.
* Малые утечки (≲ 1 % расхода) локализуются подбором по невязкам ненадёжно: при сигнале на уровне шума подбор может указать не то ребро (пример — heldout-v1 #5011).
* После исключения неисправного расходомера баланс его группы выключен; утечка в этот период может остаться у D1 «неоднозначной» (heldout-v2 #8010 — её подтвердил только D2).
* Генератор допускает медленные утечки, окно ответа которых не помещается в 900-секундный прогон; такие события цензурируются оценщиком (в test-v2 — 2 из 10).
* Изменение публичного режима обрабатывается защитным окном и перебазировкой невязок через 120 с (при отсутствии дефицита баланса): утечка, начавшаяся одновременно с командой, детектируется по балансу, но может быть обнаружена позже.
* Рост шума датчика без смещения сейчас не классифицируется как неисправность; залипание и малые смещения часто остаются «нормой» (recall класса sensor_fault у классификатора низкий — см. `docs/validation.md`).
* Волновая локализация требует резкого фронта и высокой частоты опроса (50 Гц); при 1 Гц работает только подбор по невязкам: для крупной утечки это десятки метров (каталог `leak_abrupt_e4_lowrate`: 1140 м при истине 1111 м), для малой — до сотен метров или соседнее ребро.
* Формула прямого участка `x = (L + c(t_L − t_R))/2` применима только к однородной трубе между датчиками; на сети используется перебор кандидатов по временам пробега.

## Инфраструктура
* Бэкенд — локальный, один пользователь, без аутентификации; доверенная локальная модель.
* Первое открытие приложения требует сети/сервера раздачи; после загрузки симуляция и D0/D1 работают офлайн; D2 — с встроенным артефактом модели.
