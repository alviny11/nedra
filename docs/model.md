# PipeTwin — реализованная модель

Документ описывает то, что **реализовано и проверено** в коде (`packages/physics-core`, `packages/diagnostics-core`). Всё в SI, давление абсолютное.

## 1. Объект и уровни моделей

| Уровень | Статус | Где |
|---|---|---|
| Стационарная сеть (Newton по расходам и узловым давлениям) | реализовано | `steady/hydraulics.ts` |
| Связка гидравлика ↔ температура/состав ↔ вязкость/плотность | реализовано (итерации до сходимости) | `steady/initialize.ts` |
| **M0** — нестационарная жидкость, MOC, режим 1 «фиксированные опорные ρ, c; вязкость(T, Y_w)» | реализовано | `transient/network.ts` |
| Консервативный решатель с переменными свойствами (режим 2) | **не реализован** | — |
| M1 — замороженная однородная смесь | только акустический калькулятор (формула Вуда) в UI | `fluids/fluidModel.ts::woodSoundSpeed`, `apps/web/src/app/M1Panel.tsx` |
| M2 HEM, drift-flux, two-fluid | не реализованы | интерфейс `MODEL_CAPABILITIES` сообщает статус |

Расчётная сеть демонстратора — жидкость **после первичной сепарации**: 9 труб (e1…e9), насос Н-1, регулирующая задвижка ЗД-1, задвижка сброса ЗД-2 (нормально закрыта), два куста с замером расхода (источники заданного массового расхода), граница давления УПН, буферная ёмкость, отдельный водовод С-1 → КНС. Кусты-1/2, газожидкостные линии и газовый выход — **контекст** (рисуются пунктиром, не рассчитываются).

## 2. Свойства среды (`fluids/fluidModel.ts`)

Переменная состава — массовая доля воды `Y_w`; объёмная доля `α_w = (Y_w/ρ_w)/(Y_w/ρ_w + (1−Y_w)/ρ_o)`.

* плотность фаз: `ρ_k = ρ_ref,k [1 + (p−p_ref)/K_k − β_k (T−T_ref)]` (линейная, узкий диапазон);
* смесь: `1/ρ = Y_w/ρ_w + (1−Y_w)/ρ_o` (то же, что усреднение по объёмным долям);
* теплоёмкость по массовым долям; модуль упругости по Вуду `1/K = Σ α_k/K_k`; `c = sqrt(K/ρ)`;
* вязкость нефти: `ln μ = a + b/T` (две точки: 22 мПа·с при 20 °C, 11 мПа·с при 40 °C) — **синтетика**;
* вязкость воды: лог-интерполяция табличных значений чистой воды при 0.1 МПа (без экстраполяции);
* эффективная вязкость В/Н эмульсии: `μ_oil(T)·(1−α_w)^−2.5`, только ветвь α_w ≤ 0.40, `calibrated: false`;
  инверсия эмульсии не моделируется; выход за границу → `PROFILE_OUT_OF_RANGE`.
* граница фаз: `p ≥ minPressurePa` (3.5 бар а для нефти после сепаратора 4.2 бар а); ниже — `UNSUPPORTED_PHASE_REGIME`, расчёт останавливается, последний валидный шаг сохраняется.

Скорость волны в трубе: `c = [ρ (1/K + χ D/(E e))]^−1/2`, χ из модели закрепления (`expansion_joints` 1, `anchored_upstream` 1−ν/2, `anchored_throughout` 1−ν²) — тонкостенное приближение.

## 3. Трение (`friction/friction.ts`)

`f_D` — Дарси. Re ≤ 2000: `64/Re`; Re ≥ 4000: Colebrook-White (Newton от начального Haaland); 2000…4000: кубическая интерполяция Эрмита с согласованными наклонами (непрерывно, без скачков; универсальной точности в переходной области не заявляем). `f|u|` при `u → 0` берётся по ламинарному пределу `64ν/D`. Haaland проверен против Colebrook (≤ 2 %), Churchill — для сравнения.

В MOC используется **запаздывающий коэффициент трения**: `f(Re)` в узлах сетки пересчитывается раз в ≤ 0.1 с (между пересчётами — интерполяция к основанию характеристики); при локальном `Re ≤ 2000` всегда точная ламинарная формула. Это ускоряет решатель в ~5 раз; на тестах стационарного состояния и гидроудара ошибка не видна.

## 4. Стационарная инициализация (`steady/`)

Неизвестные — массовые расходы всех звеньев и давления свободных узлов. Звенья: труба `p_i − p_j − ρg(z_j−z_i) − ΔP_f(ṁ) = 0` (трение суммируется по ячейкам с вязкостью ячейки), насос `p_i − p_j + ρgH(Q,s) = 0`, клапан `p_i − p_j − K(θ)ṁ|ṁ|/(2ρA²) = 0`, закрытый клапан `ṁ = 0`. Узлы: баланс массы. Newton с масштабированием (1 бар / 1 кг/с) и backtracking line search; обратный клапан насоса — активное множество. Не сошлось → `STEADY_STATE_NOT_FOUND` (без случайных начальных расходов).

Внешний цикл: гидравлика → стационарная температура (точная экспонента по ячейке с диссипацией трения, энтальпийное смешение в узлах) и состав → вязкость ячеек и опорная плотность трубы → повтор до `|ΔT| < 1e−7 K`, `|Δṁ|/ṁ < 1e−10`.

## 5. Нестационарная гидравлика M0 (`transient/network.ts`)

Для каждой трубы (ρ, c постоянны на прогон):

```
p_t + ρ c² u_x = 0,      u_t + p_x/ρ = −g z_x − f u|u|/(2D)
J± = p ± Z u,  Z = ρc,   dJ+/dt = −Z F вдоль dx/dt = +c,  dJ−/dt = +Z F вдоль dx/dt = −c
```

Сетка: число участков по целевой длине (25 м) и минимуму 6 на трубу; общий шаг `dt = min L_j/(n_j c_j)`; при `Cr_j = c_j dt/Δx_j < 1` — линейная интерполяция в основании характеристики (диссипативна для крутых фронтов; на длинных трубах демо Cr ≥ 0.96, на e1 Cr = 0.88). Трение полунеявное `u_P|u_foot|`. Рельеф: член `ρ g (z_P − z_foot)` с той же интерполяцией `z`, поэтому покоящаяся жидкость с рельефом не начинает течь (тест).

Узлы: для каждого конца трубы приходящая характеристика `p = C + B u_out`; баланс `Σ ρ_j A_j (p − C_j)/B_j = инжекция`. Граница давления — заданное `p`; источник — заданный `ṁ`; насос/клапан — скалярное монотонное уравнение по расходу между двумя портами (насос: `H = h0 s² + h1 s Q + h2 Q|Q|` — МНК-квадратика по паспорту, подобие без деления на ноль при `s = 0`; клапан — аналитический корень квадратного уравнения; закрытие → `Q = 0`). Динамика: насос — инерционное звено первого порядка по частоте, задвижка — ограниченная скорость хода.

**Утечка** — скрытая внутренняя точка сетки (ближайшая к заданной координате; ошибка привязки показывается оператору): две скорости (слева/справа), обе характеристики и отверстие `q = C_d A_h s(t) sqrt(2(p−p_ext)/ρ)` решаются совместно аналитически (квадратное уравнение по `sqrt(p−p_ext)`). `s(t)` — доля **площади** (smoothstep). `p ≤ p_ext` → `UNSUPPORTED_PHASE_REGIME` (обратный приток не поддержан). Публичная топология (edgeId) при этом не меняется.

Масса: для линейной модели сохраняется `M = Σ ∫ (ρA + A(p−p_ref)/c²) dx`; бухгалтерия `ε_M = M(t) − M(0) − ∫(ṁ_in − ṁ_out − ṁ_L)dt` проверяется в тестах.

## 6. Температура и состав

Конечные объёмы между узлами сетки; потоки массы — интегралы MOC-потоков за интервал переноса (подшаги с `C_tr = 0.5`, ≤ 1 с). Переносятся масса ячейки, масса воды и энтальпия `h = c_p(Y)T` (консервативно, значения на гранях — MUSCL с ограничителем van Leer по upwind). Теплообмен — Strang: ½ шага точная экспонента `T∞ + (T−T∞)exp(−U π D_o Δt/(ρ A c_p))` + нагрев трением, перенос, ½ шага. Узлы — смешение по массе и энтальпии; узел без притока сохраняет прежнее состояние (явная ветка, без деления на ноль). После переноса пересчитывается вязкость узлов сетки.

## 7. Модель измерений (`sensors/`)

`τ ẏ_f + y_f = h(U)` (точное решение для кусочно-линейного входа на шаге), задержка, `y = y_f(t_n + j − δ) + bias + ε`, квантование, насыщение (`quality: saturated`), пропуски (`valueSI: null`, `quality: missing`), джиттер метки времени. Случайные потоки независимы по `(seed, sensorId)`. Скрытые неисправности (смещение, дрейф, залипание, рост шума, пропуски) подмешиваются только генератором.

## 8. Диагностика (`diagnostics-core`, без доступа к истине)

* **Наблюдатели**: та же публичная модель без утечек, граничные условия — измерения датчиков роли `boundary_input` (давление сепаратора/УПН/водовода, расходы кустов; ЭСС-фильтр τ = 0.25 с для давления и 3 с для расхода), публичные команды. `fixed`: вязкость по паспорту при опорных T и Y_w, перенос выключен (D0). `measured`: переносит измеренные T и обводнённость (α_w → Y_w по паспорту) (D1/D2). Прогноз датчика проходит через тот же публичный фильтр датчика.
* **Невязки**: 1-с окна; калибровка 32…180 с (медиана, 1.4826·MAD, пол по видам датчиков); двусторонний CUSUM (k = 0.75, h = 25).
* **Интегральный баланс**: окно 60 с, приток/отток по расходомерам минус изменение запаса наблюдателя (та же линеаризованная масса); σ не меньше паспортной оценки шума расходомеров ×1.5.
* **D0**: |z| > 6 в течение 10 с на любом датчике давления → тревога «утечка».
* **D1**: NORMAL → SUSPECTED → CONFIRMED/AMBIGUOUS → RECOVERING. Утечка: дефицит баланса > 6σ и хотя бы одно из: датчик давления ниже расчёта (CUSUM); ≥ 2 расходомера в «утечечном» направлении (приток выше / отток ниже расчёта); один такой расходомер **и** отрицательный фронт волны на ≥ 2 датчиках давления, не объяснимый публичной командой. Без баланса — ≥ 2 датчика давления и картина расходомеров.
* **Неисправность датчика (D1)**: один датчик > 8σ, остальные < 3σ; для датчика давления — при нормальном балансе; для расходомера — без подтверждения давлением и без фронта волны. Если отклонение расходомера направлено «как при утечке» в его зоне баланса, этого мало: такой же сигнал даёт утечка, которую видит только этот расходомер (например, на e7 между ЗД-1 и УПН). Расходомер объявляется неисправным, только если есть положительный признак неисправности — **скачок** (полное отклонение за ≈ 5 с) при работающих высокочастотных датчиках давления и отсутствии фронта; иначе состояние «неоднозначно» (`FLOW_OR_LEAK`), расходомер **не** исключается. Исключённый датчик выводится из невязок и баланса своей группы. Известные публичные команды: защитное окно 90 с; через 120 с после команды (если нет дефицита баланса) смещения невязок перебазируются.
* **D2**: D1 + мультиномиальная логистическая регрессия по 21 причинному признаку; не подавляет сильную физическую тревогу (баланс > 12σ или ≥ 3 датчика), может подтвердить утечку раньше при p(leak) > 0.8 и физической поддержке (баланс > 3σ или CUSUM давления), может перевести слабую тревогу в «неоднозначно». Не подтверждает утечку, пока у одного расходомера виден «скачок без фронта» (решает изоляция D1). Если утечку подтвердил только классификатор, а физически её видят баланс и один расходомер, в диагнозе есть строка `SINGLE_METER`: неисправность этого расходомера не исключена. Без артефакта — `ML unavailable`, D2 = D1.
* **Локализация**: (1) по временам прихода фронта: детектор отрицательного скачка на высокочастотных невязках (порог 6σ, 3 отсчёта, момент — 30 % амплитуды), кандидаты на публичных рёбрах с шагом 10 м, времена пробега по физически связанным путям (насосы и открытые клапаны пропускают, границы давления — нет), исключение неизвестного t0 МНК, неопределённость времени `σ_i² + (0.015 τ_i)²`, робастное отбрасывание несогласованных приходов; (2) медленная утечка — подбор по невязкам: собственная стационарная модель наблюдателя с гипотетическим отбором в точке (шаг 50 м, уточнение 10 м), МНК по амплитуде с априорной оценкой из баланса; (3) пока нет ни фронта, ни подбора, ни значимого падения давления — только **зона баланса** в дефиците (метод `mass_balance_zone`: перечень участков контрольного объёма без точки на ребре). Интервал — множество допустимых кандидатов, **не** 95 %-ный доверительный интервал; доля случаев, когда истинное ребро попало в набор кандидатов, измеряется оценщиком (`candidateSetCoverage`).

## 9. Численные ограничения шага

`dt` фиксируется сеткой (Courant ≤ 1); ускорение воспроизведения меняет только отношение модельного и реального времени; при нехватке CPU показывается фактическая скорость. NaN/Inf → `NUMERICAL_DIVERGENCE` без замены нулём; массовое «подрезание» долей и давления не используется.
