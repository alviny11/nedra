# Подготовка данных, обучение RF и прогноз двух кейсов

`reproduce.py` строит результат из пяти исходных CSV, без чтения готовых
`master_segments.csv`, `training_between.csv`, модели из `backend_bundle`
или подготовленных признаков из этого каталога. При каждом запуске данные
обрабатываются заново, формируются признаки и обучается Random Forest.

## Запуск

Из корня репозитория, Python 3.12, отдельное окружение:

```bash
python3.12 -m venv .venv-reproduction
source .venv-reproduction/bin/activate
python -m pip install -r requirements.txt
python forecast.py
npm run build:web
```

Эта команда обучает модель заново и обновляет CSV, который использует сайт.
При `npm run dev` после пересчёта обновите страницу. Для production/preview
пересоберите фронтенд; размещённый сайт потребует публикации новой сборки.
Модель, таблицы и отчёт сохраняются в новой папке
`output/reproduction-runs/run-*/artifacts/`.

Для отдельного запуска без обновления сайта:

```bash
python reproduce.py --output-dir /tmp/nedra-reproduction-run2
```

Каждому запуску нужна новая папка. Существующая папка не перезаписывается.
Пять исходных файлов по умолчанию читаются из `data/ili`; путь можно передать
через `--input-dir`. Входные файлы проверяются по SHA256 из
`backend/reproduction/spec.json` до обучения.

`requirements.txt` предназначен только для этого отдельного окружения.
Зависимости веб-приложения и API остаются прежними.

## Что получается

В `output/reproduction/` создаются:

- `training_between.csv`: 614 строк и 75 столбцов, подготовленных из исходников;
- `predict_features.csv`: подготовленные 525 сегментов первого кейса;
- `case1.joblib`: заново обученные imputer и Random Forest;
- `result.csv`: 2000 строк, сначала 525 сегментов кейса 1, затем 1475 кейса 2;
- `case2_reference.csv`: обследования, использованные существующим расчётом второго кейса;
- `corrosion_audit.csv`: сводка пятого исходного файла по участкам;
- `report.json`: хеши исходников и результата, seed, версии, признаки,
  размеры таблиц.

`reproduce.py` сохраняет результаты отдельно. `forecast.py` запускает тот же
пайплайн и атомарно обновляет `data/forecasts/result.csv` после проверки структуры и допустимости результата.
При ошибке подготовки или обучения рабочий CSV остаётся прежним.
Фронтенд встраивает этот файл при сборке, API читает его с диска.
Старый `backend_bundle` больше не участвует в обычном пересчёте прогноза.
## Пять исходных файлов

| Файл | Роль |
| --- | --- |
| `pot_south.csv` | Паспорта: идентификаторы, длины, диаметры, номинальные толщины, даты ввода и категории |
| `altitudes_south.csv` | Высота и уклон по сегментам, окрестности высот; профиль кейса 2 |
| `vtd_south_train.csv` | Измерения толщин для базы и целевой переменной RF; опорные обследования кейса 2 |
| `tech_mode_for_embedings_with_length_with_temperatures_ids16.csv` | Временные агрегаты режимов для RF |
| `repcorr_south.csv` | Сохраняется и проверяется, сводка включается в аудит; показателей этого файла среди 66 входов текущего RF нет |

из `repcorr` в обучение без изменения модели: этого не делает текущая реализация.

## Подготовка первого кейса

1. Паспорта задают сетку по 10 м: `ceil(length_m / 10)` сегментов. Категории
   материала, покрытия и грунта кодируются в отсортированном порядке по всем
   паспортам. Пробелы по краям удаляются, пропуски получают `- Нет данных -`.
2. Высоты агрегируются внутри сегмента: среднее, минимум, максимум и линейный
   уклон `polyfit`. Пропуски высот интерполируются в обе стороны. Рассчитываются
   отклонения от среднего и диапазоны высот в окнах 5, 11 и 31 сегмент.
3. Базовые обследования привязываются с исторической линейной поправкой:
   `x = Distance + 0.06 + 7.26 * (Distance + offset) / 5248.4`.
   Смещения соседей: −44.9 м для 1250009490, 0 для 1250022871,
   5248.4 м для 1250011604. Формула продолжается на соседние участки.
4. Берётся минимальная остаточная толщина среди непропущенных измерений
   внутри сегмента; точки вне `[0, length_m)` исключаются. База интерполируется
   в обе стороны, оставшиеся пропуски заполняются номинальной толщиной.
   Правила заполнения сохранены. Целевые обследования не сдвигаются и не
   интерполируются: строки без фактического измерения исключаются из обучения.
5. Режимы усредняются по календарному дню. Нулевая температура `t_mix` считается
   пропуском. Окно наблюдений: `start < day <= end`; окно последних 365 дней:
   `day > end - 365 дней`. Рассчитываются средние, стандартные отклонения,
   последние средние, покрытие, простой и сумма жидкости.
6. Добавляются возраст на целевую дату, горизонт в годах по 365.25 дней,
   относительная базовая толщина и её средние/минимумы в окнах 3, 5 и 11.
   Историческая скорость сохраняется в таблице, но не входит в 66 признаков RF.
7. Порядок строк фиксирован: период 2018-09-23 → 2022-07-06 по участкам
   1250009490, 1250011604, 1250022871; затем 2022-07-06 → 2023-12-01 по
   1250009490 и 1250011604. Всего 561 + 53 = 614 строк.
8. Целевая величина `rate_frac = (base - actual) / nominal / horizon`.
   Полный список признаков и их порядок зафиксированы в `spec.json`.

Медианное заполнение обучается только на 614 обучающих строках,
`keep_empty_features=True`. RF: 300 деревьев, `max_features=0.8`,
`min_samples_leaf=12`, `random_state=42`, `n_jobs=2`.
Прогноз первого кейса относится к 1250022871 на 2023-12-01 от базы 2022-07-06.
Толщина рассчитывается как `base - rate * nominal * horizon`, ограничивается
снизу 0.1 мм, сверху номиналом и предыдущей базой. Округление до шести знаков
сохраняет ограничение «без роста».

## Второй кейс

Обучения нет. Вызывается существующая функция `wall_forecast.forecast.run_case2`
на исходных паспортах, профилях и обследованиях. Объект 1250009583,
дата 2022-07-01, окно сглаживания 1000 м, коэффициент разброса 0.5.
Нормированная высота распределяет среднюю относительную потерю толщины по длине.
Округление CSV — четыре знака. Состав опорных обследований и правила заполнения
толщины сохранены, включая ранее обсуждавшиеся особенности качества данных.

## Воспроизводимость

Seed 42, порядок признаков и параметры RF зафиксированы в коде и `spec.json`.
Тесты выполняют два независимых запуска из пяти исходных файлов и проверяют
повторяемость подготовленных таблиц и результата. Проверяются также структура
обучающей выборки, уникальность ключей и сохранение рабочего CSV при ошибке.

В `report.json` записываются хеши полученных файлов и версии библиотек.
Хеш результата — идентификатор конкретного запуска, а не условие допуска:
сравнения с заранее сохранённым прогнозом нет.

Проверенное окружение: Python 3.12.10, macOS arm64, NumPy 2.5.4 с Apple Accelerate,
Pandas 3.1.1, scikit-learn 1.9.1, SciPy 1.18.1. Фиксированный seed не гарантирует
побайтовое совпадение между разными реализациями BLAS/LAPACK.
Повторяемость запуска не заменяет оценку качества на независимых измерениях.
