# Прогноз толщины: этапы 2–5

## Просмотр в приложении

Главный экран сохраняет исходную технологическую схему. Два её трубопровода
открывают подробные отчёты прямым нажатием: e4 («Труба 1») — MAIN-2,
e6 («Труба 2») — MAIN-4. Это точки навигации на условной схеме, а не утверждение
о совпадении реальной и синтетической гидравлической сети. Отдельного каталога
или плашек над картой нет; переключатель внутри отчёта содержит только эти два
объекта. Остальные исходные группы сохраняются в данных, но не выставлены как
дополнительные трубы интерфейса. Режим расстановки утечки на схеме имеет приоритет
над открытием отчёта; другие трубы по-прежнему выбираются в инспекторе.

Браузер использует локальный снимок данных, который входит в сборку. Обновить его
после нового расчёта можно из `backend`:

```bash
python -m pipetwin_corrosion.export_ui --data-dir /path/to/source_csv --results /path/to/results --out ../apps/web/src/features/pipelines/real-data.json
```

Таблица и графики используют одну выборку сегментов. Историческая дата ограничивает
показ измерений; будущий прогноз скрывается на историческом графике. Экспорт CSV
всегда явно подписан своей датой и содержит все сегменты выбранной основной группы,
без влияния поискового фильтра. Пустые сегменты не выданы за обследованные.

Во вкладке «Режим и утечки» доступен **явный учебный перенос** относительного
положения сегмента на выбранную трубу действующей синтетической сети. Реальная
геометрия и датчики ещё не перенесены в решатель. Пользователь выбирает трубу и
диаметр отверстия; событие разрешено оператору после 180 секунд калибровки.
Навигация не останавливает и не переинициализирует workers. Интервал 180 секунд
не гарантирует качество калибровки, если в это время уже произошло другое событие.

Проверка браузера (при запущенном `npm run dev`, Chromium установлен для Playwright):

```bash
npx playwright test -c tests/e2e/pipelines.config.ts
```

Автономная сборка: `npm run build:single -w @pipetwin/web`.

Автономный модуль `backend/pipetwin_corrosion` дополняет PipeTwin. Он не меняет
симулятор, API или интерфейс. На входе шесть CSV организаторов; на выходе сетка,
история обследований, проверка на прошлых ВТД и первый прогноз. Используются
только pandas и NumPy; scikit-learn для этого baseline не нужен.

## Запуск

Из каталога `backend`:

```bash
python -m pipetwin_corrosion.pipeline --data-dir /path/to/source_csv --out /path/to/results
python -m unittest discover -s tests -p 'test_corrosion.py' -v
```

В существующем backend зависимости уже перечислены. Для отдельного окружения:

```bash
python -m pip install -r requirements-corrosion.txt
```

Файлы не копируются в репозиторий автоматически. Имена входных CSV фиксированы
в `FILES` модуля. Контрольные суммы и версии библиотек записываются в `audit.json`.
Алгоритм детерминирован; seed=42 указан в манифесте, случайных операций нет.

Параметры:

- `--target-date YYYY-MM-DD`: целевая дата. Без параметра берётся последняя дата
  режима только как демонстрационное допущение, **не официальная дата T**.
- `--ids 1250009490,1250011604`: выбрать участки для итогового прогноза.
  Обучение и проверка по-прежнему используют весь допустимый входной набор.
- `--model hold|constant_rate|ridge_rate`: по умолчанию прозрачный constant_rate.
  Это базовое решение, не победитель подбора по скрытому тесту.
- `--defect-assignment anchor|overlap_start`: по умолчанию `floor(Distance/10)`.
  Второй режим предназначен для проверки чувствительности: предполагает, что
  Distance — начало дефекта, Feature Length — его осевая длина в мм, и переносит
  наблюдаемую толщину на пересекаемые сегменты. Это допущение, не подтверждённая
  семантика файла и не измерение положения самой глубокой точки дефекта.

## Подготовка и качество данных

1. Паспортные длины простых участков из километров переводятся в метры.
   Нумерация локальная для каждого `id`: [0,10), [10,20), ...; последний сегмент
   может быть короче 10 м. Конечная точка трубы относится к последнему сегменту.
   Связи `direction` и `group` сохраняются; состав двух конкурсных труб не угадан.
2. Высоты интерполируются по расстоянию. Сохраняются средняя высота, уклон и
   положение относительно низшей точки участка. Это статические признаки,
   а не расчёт водного слоя или трёхфазного потока.
3. ВТД вне паспорта, некорректные толщины и записи без измеренной остаточной
   толщины исключаются из меток; причины и row_id записаны в `vtd_rejected.csv`.
   Используется Distance: в текущем наборе он совпадает с Distance_adjusted.
4. Метка — минимальная **зарегистрированная** остаточная толщина в сегменте.
   Отсутствие дефектов не доказывает отсутствие утонения. Пустые сегменты имеют
   NaN, статус `unobserved`, не превращаются в номинальные обучающие метки.
   Внутренние и внешние потери металла сохраняются: задача о минимальной стенке,
   а не только о внутренней CO2-коррозии.
5. Для MAIN-1 дата ВТД 2014 предшествует паспортному вводу 2016; медианная
   стенка ВТД также расходится с паспортом. Наблюдения сохранены, но исключены
   из обучения и стартовых фактических толщин. Прогнозы этих объектов явно
   помечены `has_excluded_precommission_vtd` и основаны на номинальном допущении.
6. УЗТ привязывается к сегментам как **точечный** замер, не как сегментный минимум.
   Мониторинг коррозии связывается только по точному ID и допустимому расстоянию.
   Непривязанные записи сохраняются. Эти два источника не входят в первый baseline:
   нет переносов между разными трубами и интерполяции будущей химии назад.
7. Из режима берутся численные средние и стандартные отклонения по доступным
   дням заданного интервала; внутридневные дубли усредняются. Пропущенные годы
   не заполняются будущими значениями. `regime_coverage` показывает долю дней.
   Это признаки ретроспективного восстановления на дату T, когда режим до T
   дан организатором; будущий режим эксплуатации не прогнозируется.
8. `pit_corrosion_intensity` исключён из-за неизвестного происхождения.
   `p_start_fact/p_end_fact` исключены: заполненные значения нулевые. `d_mm`
   не используется из-за неоднозначных единиц; диаметр берётся из паспорта.
   `t_mix` исключён из-за неоднозначных нулей; t_start/t_end используются как есть.
   q, gas_content_rate и расчётные p_start/p_end — исходные численные признаки
   без заявлений об их единицах и без физического преобразования в доли фаз.
9. Все паспортные показатели остаточного ресурса, результатов обследований,
   последующих ремонтов и готовые оценки опасности отсутствуют в списке признаков.
   Однако паспорт/рельеф остаются снимками: полная история замен неизвестна.

## Модели

- **hold**: последняя измеренная толщина или номинал без изменения.
- **constant_rate**: медианная скорость утонения; сначала медиана по каждому
  объекту/дате, затем медиана этих величин, чтобы плотные отчёты не доминировали.
- **lifetime_extrapolation**: для проверки между ВТД скорость (номинал − последняя
  толщина) / возраст к последнему обследованию. Не идентифицирует один дефект.
- **ridge_rate**: линейная регрессия скорости с L2-регуляризацией alpha=100,
  без подбора на проверочных данных. Признаки: паспорт, рельеф, положение, возраст,
  горизонт, стартовая толщина и режим. Пропуски заполняются медианами **обучающей**
  части, затем признаки стандартизуются. Каждый объект/дата имеет равный суммарный
  вес. Предсказанная скорость ограничена снизу нулём, толщина — нулём.

Положительный прирост наблюдаемой толщины возможен из-за ремонта, несовпадения
привязки и обследований. Он не удаляется из проверки. При обучении скорости
отрицательная потеря обрезается до нуля — явное упрощение baseline. Прогнозы,
дошедшие до нуля, не означают установленную дату отказа.

## Проверка без будущих меток

**Между ВТД:** сопоставляются сегменты с наблюдениями на обе даты. Обучающие
переходы заканчиваются не позже предыдущего ВТД проверочного перехода. Если
таких переходов ещё нет, используется явно указанная запасная оценка скорости
за срок службы из уже известных первых ВТД. Реальные режимы разрешены до T,
так как это условия задачи. Последующая целевая толщина не участвует в признаках.

**До первого ВТД:** исключается вся основная группа MAIN, а не случайные строки.
Обучающие метки других групп должны предшествовать целевой дате. Стартовая толщина
— паспортный номинал, УЗТ проверяемого объекта не используется. Для самого раннего
допустимого первого ВТД более ранних чужих меток нет: оценивается только hold,
обучение не имитируется. Для другого случая доступна только одна обучающая группа;
это слабая, небольшая проверка переноса, не полноценная оценка на двух неизвестных
конкурсных трубах. Другие окна/случайные сегменты не выдаются за независимые трубы.

Метрики: MAE, RMSE, bias в мм; Pearson r, его квадрат и отдельно обычный R².
У постоянного прогноза корреляция не определена и не подменяется нулём/единицей.
Метрики разбиты по случаю, дате и горизонту; сравнивать модели следует в одном fold.
Все результаты условны на наличие зарегистрированных дефектов. Пространственная
зависимость сегментов и неопределённость привязки ограничивают обобщение.

## Выходные файлы

- `assets.csv`, `segments.csv`: паспортные связи и полная сетка.
- `inspection_history.csv`: сетка обследований, наблюдаемые минимумы и пропуски.
- `uzt_linked.csv`, `corrosion_linked.csv`: привязанные дополнительные источники.
- `training_lifetime.csv`, `training_transitions.csv`: обучающие примеры и признаки.
- `validation_predictions.csv`, `validation_metrics.csv`, `folds.json`: воспроизводимая проверка.
- `result.csv`: ровно id, segment_id, thickness_pred для всех выбранных сегментов.
- `prediction_details.csv`: дата основания, источник стартовой толщины, модель,
  обучающая выборка, доля доступного режима и флаги ограничений.
- `models.json`: коэффициенты/преобразования ridge, если выбран этот вариант.
- `audit.json`, `REPORT.md`: происхождение, ограничения и читаемый отчёт.

Финальный прогноз обучается на всех допустимых метках до выбранной даты T;
это отдельно от исторической проверки. У сегментов без фактического основания
старт — номинальное допущение, и это видно в details. Первый result.csv готов
для проверки формата и демонстрации, но его нельзя считать официальной сдачей
без согласования объектов, отсчёта сегментов и даты T.
